Stored only in this browser (localStorage). No server involved.
Leave Client Secret blank and register the app as Desktop, Mobile, Single-Page App to use PKCE — no secret, no backend, a plain static page. Fill in Client Secret only if you're deliberately using a Traditional Web App type instead (e.g. to reuse an app that already has elevated access a fresh public-client app wouldn't have) — the secret then lives only in this browser's localStorage on this machine. Scopes needed either way: data:read data:write account:read.
Provisioning (do this once per hub): APS apps only see a BIM 360 / ACC hub's data after someone with Account Admin rights on that hub adds the Client ID above under Account Admin › Custom Integrations › Add Custom Integration and enables the Docs product. This is enforced by Autodesk for every auth type — there's no way around it from this app's side, and your own project-edit permission doesn't grant it. It's a one-time, low-friction ask: it only allow-lists the Client ID, it doesn't hand out any access beyond what you already have as a project member.
"api access deny" on Download all data? Reading current custom attribute values uses a different, older BIM 360 endpoint than writing them does, and it isn't enabled on every account/app the same way — it's a separate on/off switch Autodesk controls, not something 3-legged vs. 2-legged sign-in changes. The tool still exports name/type/description when this is blocked, just without attribute columns. If you need those too, Autodesk's own guidance for this is emailing bim360appsactivations@autodesk.com with subject "BIM 360 Docs – API Activation Request."
